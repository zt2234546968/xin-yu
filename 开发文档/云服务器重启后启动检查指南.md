# 云服务器重启后启动检查指南

本文用于云服务器重启、关机后重新开机、或系统异常恢复后，快速检查并启动 `XinYu` 项目相关服务。

当前服务器规划：

```text
公网 IP：8.148.7.94
前端：Nginx 8000
后端：xinyu-backend 8081
Jenkins：8080
MySQL：3306
```

注意：`80` 端口不是本项目入口，当前项目访问地址是 `http://8.148.7.94:8000/`。

## 开机后最短流程

如果只是服务器重启后想最快确认项目是否恢复，优先执行这一段。下面各章节是详细解释和异常处理。

先看服务是否已经自动起来：

```bash
sudo systemctl status mysqld --no-pager
sudo systemctl status xinyu-backend --no-pager
sudo systemctl status nginx --no-pager
sudo systemctl status jenkins --no-pager
```

如果有服务没起来，按顺序启动：

```bash
sudo systemctl start mysqld
sudo systemctl start xinyu-backend
sudo nginx -t
sudo systemctl start nginx
sudo systemctl start jenkins
```

等待后端完全启动，再验证端口和页面：

```bash
sleep 12
sudo ss -lntp | grep -E ':3306|:8000|:8080|:8081'
curl -I http://127.0.0.1:8000/
curl -I http://127.0.0.1:8081/api/swagger-ui/index.html
```

浏览器最终访问：

```text
前端：http://8.148.7.94:8000/
Swagger：http://8.148.7.94:8081/api/swagger-ui/index.html
Jenkins：http://8.148.7.94:8080/
```

## 1. 登录服务器后先检查系统状态

```bash
date
df -h
free -h
uptime
```

如果磁盘满了，优先清理日志或旧备份，否则 MySQL、Jenkins、后端都可能启动失败。

## 2. 检查服务是否设置开机自启

```bash
sudo systemctl is-enabled mysqld
sudo systemctl is-enabled xinyu-backend
sudo systemctl is-enabled nginx
sudo systemctl is-enabled jenkins
```

正常建议都应返回：

```text
enabled
```

如果某个服务不是 `enabled`，执行：

```bash
sudo systemctl enable mysqld
sudo systemctl enable xinyu-backend
sudo systemctl enable nginx
sudo systemctl enable jenkins
```

说明：当前 Nginx 是面板安装的 Nginx，执行 `systemctl enable nginx` 时如果出现 `nginx.service is not a native service`，不是错误，只要后续状态是 `active (running)` 即可。

## 3. 一键查看运行状态

```bash
sudo systemctl status mysqld --no-pager
sudo systemctl status xinyu-backend --no-pager
sudo systemctl status nginx --no-pager
sudo systemctl status jenkins --no-pager
```

重点看每个服务是否为：

```text
Active: active (running)
```

`systemctl status` 下方可能会显示服务历史日志，例如 Jenkins 之前 sudo 失败、后端之前端口冲突、Tomcat 请求解析异常等。只要当前状态是 `active (running)`，并且后面的端口和页面验证通过，就说明当前服务正在正常运行。需要看最新完整日志时再用 `journalctl`。

如果全部正常，可以直接跳到“端口和页面验证”。

## 4. 手动启动顺序

如果服务没有自动起来，按下面顺序启动。

### 4.1 启动 MySQL

后端依赖 MySQL，所以先启动数据库：

```bash
sudo systemctl start mysqld
sudo systemctl status mysqld --no-pager
```

确认 MySQL 端口：

```bash
sudo ss -lntp | grep ':3306'
```

确认项目数据库可登录：

```bash
mysql -uxinyu -p132321 -e "SHOW DATABASES;"
mysql -uxinyu -p132321 -e "USE xin_yu_db; SHOW TABLES;"
```

如果 MySQL 刚启动完成，后端仍然失败，可以等 5 到 10 秒后再启动后端。

### 4.2 启动后端

```bash
sudo systemctl start xinyu-backend
sleep 12
sudo systemctl status xinyu-backend --no-pager
```

确认后端监听 `8081`：

```bash
sudo ss -lntp | grep ':8081'
```

确认 Swagger：

```bash
curl -I http://127.0.0.1:8081/api/swagger-ui/index.html
```

看到 `HTTP/1.1 200`、`302` 或能返回响应头，说明后端基本可用。

### 4.3 启动 Nginx

```bash
sudo nginx -t
sudo systemctl start nginx
sudo systemctl status nginx --no-pager
```

确认前端端口 `8000`：

```bash
sudo ss -lntp | grep ':8000'
curl -I http://127.0.0.1:8000/
```

如果本机 `curl` 正常，但浏览器访问不了 `http://8.148.7.94:8000/`，优先检查阿里云安全组是否放行 TCP `8000`。

### 4.4 启动 Jenkins

Jenkins 用于发布，不影响已经部署好的前端和后端访问，但建议开机后也确认它可用：

```bash
sudo systemctl start jenkins
sudo systemctl status jenkins --no-pager
```

确认 Jenkins 端口 `8080`：

```bash
sudo ss -lntp | grep ':8080'
```

浏览器访问：

```text
http://8.148.7.94:8080/
```

## 5. 端口和页面验证

一键检查端口：

```bash
sudo ss -lntp | grep -E ':3306|:8000|:8080|:8081'
```

正常应看到：

```text

8000  nginx
8080  java 或 jenkins
8081  java 或 xinyu-backend
```

一键检查本机 HTTP：

```bash

curl -I http://127.0.0.1:8081/api/swagger-ui/index.html
```

浏览器检查：

```text
前端：http://8.148.7.94:8000/
Swagger：http://8.148.7.94:8081/api/swagger-ui/index.html
Jenkins：http://8.148.7.94:8080/
```

## 6. 常见异常

### 后端启动失败，提示数据库连接失败

先确认 MySQL：

```bash
sudo systemctl status mysqld --no-pager
mysql -uxinyu -p132321 -e "SELECT 1;"
```

再重启后端：

```bash
sudo systemctl restart xinyu-backend
sleep 12
sudo systemctl status xinyu-backend --no-pager
```

### 后端启动失败，提示端口被占用

检查 `8081`：

```bash
sudo ss -lntp | grep ':8081'
```

本项目后端应只由 `xinyu-backend` 这一个 systemd 服务管理。不要再手动用 `java -jar` 启动第二个后端进程。

### 前端 8000 打不开

先查 Nginx：

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
sudo ss -lntp | grep ':8000'
curl -I http://127.0.0.1:8000/
```

再查静态文件：

```bash
ls -la /opt/xinyu/web
```

正常应看到：

```text
index.html
assets
test.jpg
```

如果服务器本机访问正常、公网不通，去阿里云安全组放行 `8000`。

### 访问 80 端口不是项目页面

这是正常现象。当前服务器 `80` 端口仍然是已有面板默认站点或旧站点，本项目不走 `80`。

正确访问：

```text
http://8.148.7.94:8000/
```

### Jenkins 能打开，但构建失败

优先看 Jenkins Console Output。如果提示 Maven 找不到，确认 Jenkinsfile 使用的是：

```bash
/opt/maven/bin/mvn clean package -DskipTests
```

如果提示 sudo 需要密码，确认：

```bash
sudo cat /etc/sudoers.d/xinyu-jenkins
```

应包含：

```text
jenkins ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart xinyu-backend, /usr/bin/systemctl status xinyu-backend --no-pager
```

## 7. 推荐恢复命令汇总

服务器刚开机后，如果不确定状态，可以直接按这组命令跑：

```bash
sudo systemctl start mysqld
sudo systemctl start xinyu-backend
sudo nginx -t
sudo systemctl start nginx
sudo systemctl start jenkins

sleep 12

sudo systemctl status mysqld --no-pager
sudo systemctl status xinyu-backend --no-pager
sudo systemctl status nginx --no-pager
sudo systemctl status jenkins --no-pager

sudo ss -lntp | grep -E ':3306|:8000|:8080|:8081'
curl -I http://127.0.0.1:8000/
curl -I http://127.0.0.1:8081/api/swagger-ui/index.html
```

确认都正常后，再打开浏览器访问 `http://8.148.7.94:8000/`。

## 8. 防火墙和安全组建议

当前项目真正需要公网访问的端口是：

```text
8000  前端页面
8080  Jenkins，建议限制来源 IP
8081  Swagger/后端调试，正式环境建议关闭公网或限制来源 IP
22    SSH，建议限制来源 IP
```

`3306` 是 MySQL，项目后端和数据库都在同一台服务器上时，不需要对公网开放。正式环境建议关闭公网 `3306`，只允许本机访问。

如果服务器安全组里存在下面这些端口，且没有明确业务用途，建议删除或限制来源 IP：

```text
21    FTP
23    Telnet
1433  SQL Server
3389  Windows 远程桌面
3306  MySQL
```

尤其是 `23` Telnet 和 `3306` MySQL，不建议对 `0.0.0.0/0` 开放。
